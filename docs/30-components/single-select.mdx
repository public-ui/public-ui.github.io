# SingleSelect

**Synonyme:** Dropdown, Auswahlfeld, Einfachauswahl, Auswahlliste mit Suche, Searchable Select

**Beschreibung:** Mit **SingleSelect** wählen Nutzende genau eine Option aus einer vordefinierten Liste aus. Die Liste lässt sich durch Texteingabe filtern, sodass auch in umfangreichen Listen schnell der passende Eintrag gefunden wird. Freie Eingaben werden nicht als Wert übernommen.

Die Komponente basiert auf einem nativen Texteingabefeld (`input type="text"`), das KoliBri nach dem WAI-ARIA-Pattern **„Editable Combobox with List Autocomplete“** mit einer eigenen Auswahlliste (Listbox) verbindet. Es wird bewusst kein natives `select`-Element verwendet; Rollen, Zustände und Tastatursteuerung setzt KoliBri selbst um.

Im Eingabefeld wird die Beschriftung (`label`) der ausgewählten Option angezeigt; der Wert der Komponente (`_value`) entspricht dem `value` dieser Option.

**Anwendungsfälle:**
- Auswahl von Titel, Anrede oder Geschlecht in Formularen
- Wahl eines Landes, Bundeslandes oder einer Region
- Auswahl einer Kategorie oder eines Status, z. B. als Filter nach einem einzigen Kriterium
- Auswahl eines Datums oder einer Uhrzeit aus vordefinierten Werten
- Einzelauswahl in Einstellungen oder Konfigurationen

### Konkrete Designentscheidungen

| Entscheidung | Begründung |
| ------------ | ---------- |
| SingleSelect ist ein eigenes Widget mit filterbarer Auswahlliste und kein natives `select`. | Das native `select`-Element bietet keine Filterung per Texteingabe, und seine Darstellung lässt sich nur eingeschränkt gestalten. Die eigene Umsetzung ermöglicht eine filterbare Auswahl mit konsistentem Verhalten über alle unterstützten Plattformen hinweg. |
| Der Öffnen-/Schließen-Pfeil ist nicht Teil der Tab-Reihenfolge. | Er dient ausschließlich als zusätzliche Unterstützung für Maus- und Touch-Nutzende. Die gleiche Funktion steht über die Pfeiltasten im Eingabefeld zur Verfügung, sodass unnötige Tabstopps vermieden werden. |
| Liefert die Filterung keinen Treffer, wird die Meldung „Keine Ergebnisse gefunden.“ unmittelbar angesagt. | Eine leere Liste wäre für Screenreader-Nutzende sonst nicht wahrnehmbar. |
| Deaktivierte Optionen bleiben sichtbar, werden bei der Tastaturnavigation aber übersprungen. | Nutzende gelangen ohne Umwege zu auswählbaren Optionen, während die deaktivierten Optionen als Information sichtbar bleiben. |

## Tastatursteuerung

<CustomKeyboardIntro />

| Taste                       | Funktion                                                                    |
| --------------------------- | --------------------------------------------------------------------------- |
| `Tab`                       | Fokus auf das Eingabefeld bzw. das nächste fokussierbare Element setzen. Eine geöffnete Liste wird dabei ohne Auswahl geschlossen. |
| `Shift+Tab`                 | Fokus auf das vorherige fokussierbare Element setzen. Eine geöffnete Liste wird dabei ohne Auswahl geschlossen. |
| `Pfeil-Taste unten`         | Liste öffnen und Fokus auf den nächsten Eintrag setzen. Nach dem letzten Eintrag folgt wieder der erste. |
| `Pfeil-Taste oben`          | Bei geschlossener Liste: Liste öffnen und Fokus auf den letzten Eintrag setzen. Bei geöffneter Liste: Fokus auf den vorherigen Eintrag setzen; vor dem ersten Eintrag folgt wieder der letzte. |
| `Pos1`/`Ende`               | Bei geöffneter Liste Fokus auf den ersten/letzten Eintrag setzen. |
| `Bild-Tasten (hoch/runter)` | Bei geöffneter Liste Fokus um zehn Einträge nach oben/unten verschieben. Wird das Listenende über- bzw. der Listenanfang unterschritten, springt der Fokus zum ersten bzw. letzten Eintrag. |
| `Enter`                     | Ist eine Option fokussiert, wird sie ausgewählt, die Auswahlliste geschlossen und der Fokus in das Eingabefeld gesetzt. Ist die Liste geschlossen, wird sie geöffnet; eine bereits ausgewählte Option erhält dabei den Fokus. Liegt der Fokus auf dem Clear-Button, wird die Auswahl entfernt. |
| `Leertaste`                 | Ist eine Option fokussiert, wird sie ausgewählt, die Auswahlliste geschlossen und der Fokus in das Eingabefeld gesetzt. Ist die Liste geschlossen, wird sie geöffnet; eine bereits ausgewählte Option erhält dabei den Fokus. Liegt der Fokus auf dem Clear-Button, wird die Auswahl entfernt. Ist die Liste geöffnet und kein Eintrag fokussiert (z. B. während der Texteingabe), wird ein Leerzeichen eingegeben. |
| `Esc`                       | Liste ohne Auswahl schließen und Fokus in das Eingabefeld setzen. Der eingegebene Text bleibt erhalten. |
| `Zeicheneingabe` (Fokus im Eingabefeld) | Liste entsprechend der Eingabe filtern. |
| `Buchstabe oder Ziffer` (Fokus auf einem Eintrag) | Fokus auf den ersten Eintrag setzen, dessen Beschriftung mit dem eingegebenen Zeichen beginnt. Das Zeichen wird nicht in das Eingabefeld übernommen. Berücksichtigt werden nur die Buchstaben A–Z und Ziffern (keine Umlaute). |

**Hinweis:** Deaktivierte Optionen werden von den Pfeiltasten, `Pos1`/`Ende`, den Bild-Tasten und der Zeichensuche übersprungen.

**Hinweis:** `Enter` sendet das umgebende Formular nicht ab, sondern öffnet die Auswahlliste bzw. wählt die fokussierte Option aus.

## FAQ

**Wann verwende ich SingleSelect und wann eine andere Auswahlkomponente?**  
Verwenden Sie SingleSelect, wenn genau eine Option aus einer vordefinierten Liste gewählt werden soll. Bei nur wenigen Optionen können Radio-Buttons ([InputRadio](../components/input-radio)) übersichtlicher sein, da alle Optionen ohne Öffnen einer Liste sichtbar sind. Bei vielen Optionen (mehr als 15) erwägen Sie eine andere Komponente wie eine Tabelle oder [Combobox](../components/combobox). Sollen neben vordefinierten Werten auch freie Eingaben möglich sein, verwenden Sie die [Combobox](../components/combobox).

**Worin unterscheidet sich SingleSelect vom Select?**  
Das [Select](../components/select) basiert auf dem nativen `select`-Element. SingleSelect ist ein eigenes Widget, das zusätzlich eine Filterung per Texteingabe bietet und sich damit besonders für umfangreiche Listen eignet.

**Kann ich einen eigenen Wert eingeben, der nicht in der Liste steht?**  
Nein. Der eingegebene Text dient nur zum Filtern der Optionen. Als Wert wird ausschließlich der `value` einer ausgewählten Option übernommen. Für freie Eingaben mit Vorschlägen verwenden Sie die [Combobox](../components/combobox).

**Wie übergebe ich die Optionen und welchen Wert liefert die Komponente?**  
Übergeben Sie die Optionen über `_options` als Liste von Objekten mit `label` (angezeigte Beschriftung), `value` (Wert) und optional `disabled` (siehe [Deaktivierte Optionen](#deaktivierte-optionen)). Der Wert (`_value`) entspricht dem `value` der gewählten Option. Ohne Auswahl bzw. nach dem Entfernen der Auswahl ist er `null`.

**Wie werden die Optionen gefiltert?**  
Ein Klick in das Eingabefeld oder auf den Pfeil öffnet bzw. schließt die Auswahlliste. Während der Eingabe werden die Optionen über eine **Substring-Suche** ohne Beachtung der Groß-/Kleinschreibung gefiltert, und der Suchbegriff wird in den passenden Optionen hervorgehoben. Passt keine Option zur Eingabe, wird „Keine Ergebnisse gefunden.“ angezeigt und von Screenreadern unmittelbar angesagt. Verlässt der Fokus das Feld und entspricht der eingegebene Text exakt der Beschriftung einer Option (ohne Beachtung der Groß-/Kleinschreibung), wird diese Option automatisch ausgewählt.

**Hinweis:** Ist bereits eine Option ausgewählt, setzt KoliBri 4.5.0 die Filterung zurück, sobald der Fokus in die Liste wechselt – etwa per `Pfeil-Taste unten` oder beim Überfahren der Optionen mit der Maus. Die Liste zeigt dann wieder alle Optionen (<kol-link _href="https://github.com/public-ui/kolibri/issues/10501" _target="_blank" _label="KoliBri-Issue #10501"></kol-link>, <kol-link _href="https://github.com/public-ui/kolibri/issues/10617" _target="_blank" _label="#10617"></kol-link>).

**Wie formuliere ich Beschriftung, Optionen und Placeholder?**  
Verwenden Sie klare, verständliche Beschriftungen (`_label`), die den Zweck der Auswahl deutlich machen. Formulieren Sie die Beschriftungen der Optionen eindeutig und gut unterscheidbar – sie werden sowohl für die Filterung als auch für die Zeichensuche verwendet. Nutzen Sie den Placeholder (`_placeholder`) nur als ergänzende Hilfe, nicht als Ersatz für Beschriftung oder Hinweis.

**Wie lang darf die Optionsliste sein?**  
Gestalten Sie die Optionsliste nicht zu lang; verwenden Sie bei Bedarf Gruppierung oder Pagination. SingleSelect selbst unterstützt keine Optionsgruppen – für gruppierte Optionen eignet sich das [Select](../components/select). Wie viele Optionen ohne Scrollen sichtbar sind, legen Sie mit `_rows` fest (siehe [Sichtbare Optionen](#sichtbare-optionen)).

**Wie gestalte ich die Auswahl im Formular nutzerfreundlich?**  
Überlegen Sie, ob ein sinnvoller Standardwert gesetzt werden sollte, um Fehlbedienungen zu minimieren. Geben Sie aussagekräftige Validierungsfehlermeldungen über `_msg` vor. Setzen Sie deaktivierte Optionen nur sparsam ein und erläutern Sie – falls für das Verständnis nötig – über `_hint`, warum eine Option nicht verfügbar ist. Setzen Sie bei Bedarf einen expliziten Senden-/Absenden-Button, um Nutzenden Sicherheit zu geben.

**Zeigt der Browser für das Eingabefeld eine Autovervollständigung an?**  
Nein. KoliBri schaltet die Autovervollständigung des Browsers für das Eingabefeld ab (`autocomplete="off"`). Ein Property `_autoComplete` wie bei den Texteingabefeldern gibt es für SingleSelect nicht; es ist als <kol-link _href="https://github.com/public-ui/kolibri/issues/10498" _target="_blank" _label="Feature-Anfrage #10498"></kol-link> erfasst.

**Kann ich SingleSelect in Tabellen oder scrollbaren Bereichen verwenden?**  
Ja, beachten Sie aber: Die geöffnete Auswahlliste wird innerhalb der Seite unterhalb des Eingabefelds dargestellt und nicht über umgebende Container gelegt. In Containern mit begrenzter Höhe und `overflow`, z. B. in den letzten Zeilen einer Tabelle, wird die Liste abgeschnitten oder nur durch Scrollen des Containers erreichbar (<kol-link _href="https://github.com/public-ui/kolibri/issues/10616" _target="_blank" _label="KoliBri-Issue #10616"></kol-link>).

**Warum ist der Öffnen-/Schließen-Pfeil nicht per Tab erreichbar?**  
Der Öffnen-/Schließen-Pfeil dient ausschließlich als zusätzliche Unterstützung für Maus- und Touch-Nutzende. Die Auswahlliste kann vollständig über die Tastatur geöffnet und bedient werden, sodass kein zusätzlicher Tabstopp erforderlich ist.

### Deaktivierte Optionen

Einzelne Optionen deaktivieren Sie über `disabled: true` im jeweiligen Options-Objekt. Deaktivierte Optionen bleiben in der Liste sichtbar, werden von Screenreadern als nicht verfügbar ausgegeben, bei der Tastaturnavigation übersprungen und lassen sich nicht auswählen.

<SingleSelectPreview
	context="feature"
	visibleProperties={['_options']}
	initialProps={{
		_label: 'Versandart',
		_options: [
			{ label: 'Standardversand', value: 'standard' },
			{ label: 'Expressversand', value: 'express', disabled: true },
			{ label: 'Abholung', value: 'pickup' },
		],
	}}
/>

### Clear-Button

<ClearButtonFeature />

Nach dem Entfernen der Auswahl wird die Auswahlliste geöffnet und der Fokus in das Eingabefeld gesetzt, sodass direkt eine neue Option gewählt werden kann. Dabei werden die Events `input` und `change` ausgelöst.

**Hinweis:** In KoliBri 4.5.0 liefern die Events `input` und `change` beim Entfernen der Auswahl nicht `null`, sondern das Objekt `{ value: null }` (<kol-link _href="https://github.com/public-ui/kolibri/issues/11205" _target="_blank" _label="KoliBri-Issue #11205"></kol-link>). `_value` und `getValue()` sind dagegen `null`.

<SingleSelectPreview
	context="feature"
	visibleProperties={['_hasClearButton']}
	initialProps={{
		_label: 'Bundesland',
		_hasClearButton: true,
		_value: 'BY',
	}}
/>

### Sichtbare Optionen

Mit `_rows` legen Sie fest, wie viele Optionen in der geöffneten Auswahlliste gleichzeitig sichtbar sind. Weitere Optionen erreichen Nutzende durch Scrollen bzw. über die Tastatur. Ohne Angabe sind fünf Optionen sichtbar.

<SingleSelectPreview
	context="feature"
	visibleProperties={['_rows']}
	initialProps={{
		_label: 'Bundesland',
		_rows: 3,
	}}
/>

## API

### Events

<EventsIntro />

| Event     | Auslöser                                                       | Value                                  |
| --------- | -------------------------------------------------------------- | -------------------------------------- |
| `click`   | Eingabefeld wird angeklickt                                    | -                                      |
| `focus`   | Komponente erhält den Fokus                                    | -                                      |
| `blur`    | Komponente verliert den Fokus                                  | -                                      |
| `keydown` | Taste wird im Eingabefeld gedrückt                             | -                                      |
| `input`   | Eine andere Option wird ausgewählt oder die Auswahl entfernt   | `value` der ausgewählten Option; beim Entfernen der Auswahl `{ value: null }` (siehe [Clear-Button](#clear-button)) |
| `change`  | Eine andere Option wird ausgewählt oder die Auswahl entfernt   | `value` der ausgewählten Option; beim Entfernen der Auswahl `{ value: null }` (siehe [Clear-Button](#clear-button)) |

Die Texteingabe zum Filtern der Optionen löst kein `input`-Event aus. Wird die bereits ausgewählte Option erneut gewählt, werden keine Events ausgelöst.

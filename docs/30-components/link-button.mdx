# LinkButton

**Synonyme:** Link mit Button-Stil, stilisierter Link, Call-to-Action-Link, Link Button, Schaltflächen-Link

**Beschreibung:** Die **LinkButton**-Komponente ist semantisch ein Link, hat aber das visuelle Erscheinungsbild eines Buttons. Sie basiert auf dem nativen HTML-Element `a`, kombiniert die Semantik der Link-Komponente mit den Design-Eigenschaften der Button-Komponente und eignet sich zur Verlinkung mit Betonung durch Button-artige Darstellung.

**Anwendungsfälle:**
- Navigation zu primären oder hervorgehobenen Bereichen einer Anwendung
- Call-to-Action-Links, die visuell als Buttons prominenter erscheinen sollen
- Navigation in Footern oder Sidebars mit Button-ähnlichem Styling
- Kontextuelle Navigation mit Button-Styling (z. B. „Weitere Informationen“)
- Rückwärts-Navigation oder ähnliche primäre Navigationsziele

## Barrierefreiheit

- Die Komponente behält die **semantische Rolle des Links**: Screenreader kündigen sie unabhängig vom Button-Erscheinungsbild als Link an und führen sie in der Linkliste auf.
- Die sichtbare Beschriftung (`_label`) ist zugleich der zugängliche Name. Screenreader geben damit denselben Text aus, den sehende Nutzende lesen; dekorative Icons und der Hinweis auf ein Tastenkürzel werden dabei nicht mitgelesen. Ist `_label` nicht gesetzt, wird das Linkziel (`_href`) als Beschriftung angezeigt und vorgelesen.
- Der LinkButton ist unabhängig von der Länge seiner Beschriftung mindestens 44 Pixel hoch und erfüllt damit in der Höhe die Zielgröße nach WCAG 2.5.5.
- Die Komponente stellt einen sichtbaren Fokuszustand bereit. Im Kontrastmodus des Betriebssystems (z. B. „Kontrastdesigns“ unter Windows) werden Fokusrahmen und deaktivierter Zustand in den Systemfarben dargestellt und bleiben dadurch unterscheidbar.

### Konkrete Designentscheidungen

| Entscheidung | Begründung |
| --- | --- |
| Verwendung des nativen HTML-Elements `a` | Der LinkButton ist semantisch ein Link, der lediglich wie ein Button aussieht. Das native Element ist von sich aus per Tastatur bedienbar (`Enter` löst den Klick aus); eine eigene Tastaturbehandlung entfällt dadurch. |
| Die Rolle des Links lässt sich nicht ändern | KoliBri bevorzugt die semantische Rolle des HTML-Elements und lässt keine Anpassung zu. Die Property `_role` ist deshalb veraltet und wird nicht mehr übernommen. |
| Deaktivierte LinkButtons sind weder per Tastatur noch per Maus oder Skript erreichbar | Das `a`-Element kennt keinen nativen deaktivierten Zustand. KoliBri ergänzt ihn, damit ein deaktivierter LinkButton wie andere deaktivierte Bedienelemente nicht mehr angesteuert werden kann. |
| Kein sichtbares Icon für das Öffnen in einem neuen Tab | Das Icon wurde außerhalb der Schaltfläche angezeigt und veränderte ihre Größe (<kol-link _href="https://github.com/public-ui/kolibri/issues/10506" _target="_blank" _label="KoliBri-Issue #10506"></kol-link>). Der Hinweis für Screenreader bleibt erhalten (siehe [Zielverhalten](#zielverhalten)). |

## Tastatursteuerung

<NativeKeyboardIntro />

| Taste       | Funktion                                                                  |
| ----------- | ------------------------------------------------------------------------- |
| `Tab`       | Fokus auf den LinkButton bzw. das nächste fokussierbare Element setzen.   |
| `Shift+Tab` | Fokus auf das vorherige fokussierbare Element setzen.                     |
| `Enter`     | Link öffnen bzw. Download starten.                                        |

`Space` öffnet den LinkButton nicht – wie bei jedem nativen Link scrollt der Browser stattdessen die Seite. Das unterscheidet den LinkButton trotz gleichen Erscheinungsbilds vom [Button](./button.mdx).

Ergänzend zum nativen Verhalten schließt `Escape` den Tooltip eines LinkButtons mit ausgeblendeter Beschriftung (`_hideLabel`), solange er angezeigt wird.

Deaktivierte LinkButtons (`_disabled`) sind nicht Teil der Tab-Reihenfolge.

## FAQ

**Wann sollte ich LinkButton statt Button verwenden?**  
Die Wahl richtet sich nach der Funktion, nicht nach dem Erscheinungsbild. Verwenden Sie LinkButton nur, wenn Sie semantisch einen Link benötigen (Navigation), die Nutzenden aber eine Button-ähnliche Darstellung erwarten bzw. der Link mit Button-Styling betont werden soll. Für echte Aktionen (z. B. Speichern, Löschen oder Formularabsendung) verwenden Sie einen <kol-link _href="../components/button" _label="Button"></kol-link>.

**Was ist der Unterschied zu ButtonLink?**  
LinkButton ist semantisch ein Link mit Button-Styling. <kol-link _href="../components/button-link" _label="ButtonLink"></kol-link> ist dagegen semantisch ein Button mit Link-Styling.

**Wie formuliere ich die Beschriftung?**  
Der Link-Text sollte das Ziel oder den Kontext der Navigation deutlich machen (z. B. „Zur Startseite“ statt „Hier“).

**Wie kennzeichne ich externe Links und Links, die sich in einem neuen Tab öffnen?**  
Verwenden Sie `_target="_blank"` nur, wenn sich der Link tatsächlich in einem neuen Tab öffnen soll. KoliBri ergänzt dafür nur einen Hinweis für Screenreader, kein sichtbares Icon (siehe [Zielverhalten](#zielverhalten)) – kommunizieren Sie das Öffnen in einem neuen Tab daher deutlich in der Beschriftung. Nutzen Sie Icons oder klare Beschriftungen, um externe Links von internen zu unterscheiden.

**Kann ich LinkButton mit Icons verwenden?**  
Ja, siehe [Icons](#icons) und [Icon-Only-LinkButton](#icon-only-linkbutton).

## Funktionalitäten

### Beschriftung und Linkziel

Die sichtbare Beschriftung wird über `_label` gesetzt, das Linkziel über `_href` (Pflichtfeld). Ohne `_label` zeigt die Komponente das Linkziel als Beschriftung an.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_label', '_href']}
	initialProps={{ _label: 'Zur Startseite', _href: '#' }}
/>

### Varianten

Die Darstellung wird über `_variant` gesteuert. Die Themes steuern welche Varianten zur Verfügung stehen und welche der Standardwert ist. Hier sind <kol-link _href="https://develop--kolibri-public-ui.netlify.app/#/button/variants?theme=default" _target="_blank" _label="die anderen Themes und ihre jeweiligen Varianten"></kol-link> zu sehen. Im Folgenden zeigen wir nur das Default Theme.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_variant']}
	initialProps={{ _label: 'LinkButton', _href: '#', _variant: 'primary' }}
/>

### Icons

Icons können über `_icons` hinzugefügt werden. Als String übergeben Sie die Icon-Klasse (z. B. `kolicon-house`), das Icon wird links vom Text angezeigt:

<LinkButtonPreview
	context="feature"
	visibleProperties={['_icons']}
	initialProps={{ _label: 'Startseite', _href: '#', _icons: 'kolicon-house' }}
/>

Icons können auch als Objekt mit den Positionen `top`, `right`, `bottom` und `left` angegeben werden, jeweils mit Icon-Klasse oder als Objekt mit `icon`, optional `label` und `style`.

Ein Icon ohne `label` gilt als dekorativ und wird von Screenreadern nicht ausgegeben. Trägt ein Icon eine Information, die nicht bereits aus der Beschriftung hervorgeht, übergeben Sie es als Objekt mit `label`.

### Icon-Only-LinkButton

Mit `_hideLabel` wird nur das Icon angezeigt, die Beschriftung wird als Tooltip angezeigt:

<LinkButtonPreview
	context="feature"
	visibleProperties={['_hideLabel', '_icons', '_tooltipAlign']}
	initialProps={{ _label: 'Startseite', _href: '#', _icons: 'kolicon-house', _hideLabel: true }}
/>

**Hinweis:** Das Attribut `_label` muss auch gesetzt werden, wenn nur ein Icon angezeigt wird – es wird für Screenreader und den Tooltip verwendet.

Der Tooltip erscheint nach kurzer Verzögerung, sobald der LinkButton mit der Maus berührt oder per Tastatur fokussiert wird. Er bleibt sichtbar, solange sich der Mauszeiger über dem LinkButton oder dem Tooltip befindet, und lässt sich mit `Escape` schließen. Nach einem Klick wird er ausgeblendet, bis der LinkButton verlassen und erneut angesteuert wird. Mit `_tooltipAlign` legen Sie die bevorzugte Position fest (`top`, `right` (Standard), `bottom`, `left`); reicht der Platz nicht aus, weicht der Tooltip auf eine andere Seite aus.

### Zielverhalten

Über `_target` steuern Sie, wo der Link im Browser geöffnet wird:

<LinkButtonPreview
	context="feature"
	visibleProperties={['_target']}
	initialProps={{ _label: 'Dokumentation', _href: 'https://public-ui.github.io/docs', _target: '_blank' }}
/>

**Verfügbare Targets:**

- `_self` – Der Link wird im aktuellen Tab geöffnet (Standard)
- `_blank` – Der Link wird in einem neuen Tab geöffnet

Daneben sind die übrigen Werte des nativen `target`-Attributs möglich (z. B. `_parent`, `_top` oder ein Fenstername).

Bei jedem Wert außer `_self` geben Screenreader zusätzlich den Hinweis „Öffnet in neuem Tab.“ aus. Ein sichtbarer Hinweis wird beim LinkButton nicht angezeigt (siehe [Konkrete Designentscheidungen](#konkrete-designentscheidungen)).

### Download-Links

Mit `_download` signalisieren Sie dem Browser, dass eine Datei heruntergeladen werden soll. Der Wert wird als vorgeschlagener Dateiname verwendet; ein leerer String startet den Download ohne Dateinamensvorschlag.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_download']}
	initialProps={{ _label: 'PDF herunterladen', _href: '/files/dokument.pdf', _download: 'dokument.pdf' }}
/>

### Deaktivierter Zustand

Mit `_disabled` wird der LinkButton deaktiviert. Er ist dann nicht Teil der Tab-Reihenfolge, erhält auch per Mausklick oder über die Methoden `focus()` und `click()` keinen Fokus, öffnet den Link nicht und löst keine Events aus. Screenreader kündigen ihn als nicht verfügbar an. Ist zusätzlich `_hideLabel` gesetzt, lässt sich der Tooltip mit der Beschriftung daher nicht per Tastatur aufrufen.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_disabled']}
	initialProps={{ _label: 'Deaktiviert', _href: '#', _disabled: true }}
/>

### Tastenkürzel

Mit `_accessKey` und `_shortKey` weisen Sie auf ein Tastenkürzel hin. Beide werden als Hinweis hinter der Beschriftung angezeigt; der passende Buchstabe in der Beschriftung wird zusätzlich unterstrichen. Es kann jeweils nur eine der beiden Properties gesetzt werden.

- `_accessKey`: Definiert die Tastenkombination zum Auslösen oder Fokussieren des LinkButtons. Sie wird auf das native `accesskey`-Attribut übertragen; welche Zusatztasten dafür gedrückt werden müssen, hängt von Browser und Betriebssystem ab.
- `_shortKey`: Definiert einen visuellen Shortcut-Hinweis und liest ihn in Screenreadern vor. Die Tastenkombination selbst muss von der Anwendung umgesetzt werden.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_accessKey', '_shortKey']}
	initialProps={{ _label: 'Startseite', _href: '#', _shortKey: 's' }}
/>

### Aktuelle Seite

Mit `_ariaCurrentValue` (z. B. `page`) kennzeichnen Sie den LinkButton als Verweis auf die aktuelle Seite bzw. den aktuellen Schritt; Screenreader kündigen ihn dann entsprechend an. Die Kennzeichnung wird nur gesetzt, solange `_href` dem aktuellen Ort entspricht. Diesen teilt die Anwendung KoliBri über die Funktion `setCurrentLocation` aus `@public-ui/components` mit (z. B. bei jedem Routenwechsel); ohne diesen Aufruf bleibt `_ariaCurrentValue` wirkungslos.

<LinkButtonPreview
	context="feature"
	visibleProperties={['_ariaCurrentValue']}
	initialProps={{ _label: 'Aktuelle Seite', _href: '#', _ariaCurrentValue: 'page' }}
/>

### Weitere Eigenschaften

Darüber hinaus unterstützt der LinkButton folgende Attribute:

| Eigenschaft        | Beschreibung                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `_ariaDescription` | Ergänzende Beschreibung, die Screenreader zusätzlich zur Beschriftung ausgeben; sie wird nicht sichtbar dargestellt  |
| `_ariaControls`    | Definiert, welche Elemente durch diesen LinkButton gesteuert werden (`aria-controls`)                                |
| `_customClass`     | Zusätzliche CSS-Klasse, wenn `_variant="custom"` gesetzt ist                                                         |
| `_inline`          | Displaymodus ohne Mindestgröße von 44px. Abweichend davon bleibt die Mindesthöhe beim LinkButton in KoliBri 4.5.0 erhalten. |

<LinkButtonPreview
	context="feature"
	visibleProperties={['_ariaDescription', '_ariaControls', '_customClass', '_inline']}
	initialProps={{ _label: 'Dokumentation', _href: '#', _ariaDescription: 'Navigiert zur Dokumentation' }}
/>

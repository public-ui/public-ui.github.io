# Select

**Synonyme:** Dropdown, Dropdown-Liste, Auswahlliste, Auswahlfeld

**Beschreibung:** Mit **Select** wählen Nutzende eine oder mehrere Optionen aus einer vordefinierten Liste aus.

Die Komponente basiert auf dem nativen HTML-Element `<select>` und profitiert dadurch von dessen Semantik sowie der standardisierten Unterstützung durch Browser und assistive Technologien.

Sie eignet sich für strukturierte Eingaben, bei denen ausschließlich bekannte Werte zulässig sind und keine freie Texteingabe erfolgen soll. Je nach Konfiguration unterstützt die Komponente die **Einfachauswahl** als aufklappbares Auswahlfeld oder die **Mehrfachauswahl** als Liste mit mehreren sichtbaren Zeilen. Die auswählbaren Optionen werden über `_options` bereitgestellt und können mithilfe von **Optionsgruppen** logisch strukturiert werden.

**Anwendungsfälle:**
- Auswahl eines Bundeslandes
- Sprachauswahl
- Auswahl einer Organisationseinheit oder eines Fachbereichs
- Kategorieauswahl in Formularen
- Statusauswahl aus mehreren festgelegten Bearbeitungsständen

### Konkrete Designentscheidungen

| Entscheidung | Begründung |
| ------------ | ---------- |
| Verwendung des nativen HTML-Elements `<select>` | Rolle, Tastaturbedienung, Fokusverwaltung und Ansageverhalten stammen vollständig vom nativen Element und entsprechen damit dem gewohnten Verhalten des jeweiligen Browsers. |
| Deaktivierte Optionen bleiben für Screenreader wahrnehmbar | Deaktivierte Optionen werden nicht vor assistiven Technologien verborgen, da Browser das Verbergen einzelner Optionen ignorieren bzw. dadurch fehlerhaftes Verhalten entstand. Screenreader zählen und sagen sie daher mit an, sodass die Anzahl der angesagten Optionen von der Anzahl der auswählbaren Optionen abweichen kann. |
| Mindestgröße der Optionen bei Mehrfachauswahl | In der dauerhaft sichtbaren Liste der Mehrfachauswahl (`_multiple`) haben die Optionen eine Mindesthöhe, die der barrierefreien Mindestgröße für Bedienelemente entspricht. So können sie auch mit Maus und Touch sicher getroffen werden. |
| Häkchen vor ausgewählten Optionen | Ausgewählte Optionen sind zusätzlich zur Hervorhebung durch ein vorangestelltes Häkchen erkennbar. Die Darstellung hängt davon ab, ob der Browser die Optionsliste mit den Stilen der Komponente rendert. |

## Tastatursteuerung

<NativeKeyboardIntro />

| Taste                       | Funktion                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `Tab`                       | Fokus auf die Auswahlliste bzw. das nächste fokussierbare Element setzen.                                  |
| `Shift+Tab`                 | Fokus auf das vorherige fokussierbare Element setzen.                                                      |
| `Pfeil-Tasten (oben/unten)` | Zwischen den Optionen wechseln. Je nach Browser wird die Auswahl auch bei geschlossener Auswahlliste direkt geändert. |
| `Pos1` / `Ende`             | Zur ersten bzw. letzten Option springen.                                                                   |
| Buchstabentasten            | Zur nächsten Option springen, deren Beschriftung mit dem eingegebenen Zeichen beginnt.                     |
| `Leertaste` / `Enter`       | Auswahlliste öffnen bzw. die hervorgehobene Option übernehmen und die Auswahlliste schließen.              |
| `Alt+Pfeil-Taste unten`     | Auswahlliste öffnen (u. a. unter Windows).                                                                 |
| `Esc`                       | Geöffnete Auswahlliste schließen.                                                                          |

### Bei Mehrfachauswahl (`_multiple`)

| Taste                        | Funktion                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `Pfeil-Tasten (oben/unten)`  | Fokus auf die nächste bzw. vorherige Option setzen und nur diese Option auswählen. |
| `Shift+Pfeil-Tasten`         | Auswahl um die hintereinanderliegenden Optionen erweitern.                        |
| `Strg+Pfeil-Tasten`          | Fokus verschieben, ohne die bestehende Auswahl zu verändern.                      |
| `Strg+Leertaste`             | Fokussierte Option zur Auswahl hinzufügen bzw. aus ihr entfernen.                 |

**Hinweis:** Unter macOS wird statt `Strg` in der Regel die `Cmd`-Taste verwendet.

## FAQ

**Wofür eignet sich die Select-Komponente?**  
Für die Auswahl einer oder mehrerer Optionen aus einer vordefinierten Menge an Werten, etwa bei strukturierten Formulareingaben und standardisierter Datenerfassung. Verwenden Sie die Select-Komponente ausschließlich für vordefinierte Auswahlmöglichkeiten.

**Wann eignet sich eine Combobox besser?**  
Wenn freie Eingaben möglich sein sollen, bei einer Einfachauswahl eine Such- oder Filterfunktion benötigt wird, eine große Anzahl an Optionen zur Verfügung steht oder Nutzende gezielt nach Einträgen suchen sollen. Prüfen Sie daher bei umfangreichen Auswahllisten, ob eine **Combobox** die geeignetere Komponente ist.

**Wann eignet sich eine Radio Group besser?**  
Wenn genau eine Option aus einer kleinen Anzahl (ca. 1–5 Optionen) ausgewählt werden soll und alle Optionen gleichzeitig sichtbar sein können.

**Wann sollte ich die Mehrfachauswahl verwenden?**  
Nutzen Sie `_multiple` nur, wenn eine Mehrfachauswahl fachlich erforderlich ist. Die Mehrfachauswahl erfordert Tastenkombinationen, die vielen Nutzenden nicht bekannt sind (siehe [Tastatursteuerung](#tastatursteuerung)). Prüfen Sie, ob stattdessen eine **Checkbox Group** besser geeignet ist.

**Welche Werte erwartet `_value`?**  
Bei der Einfachauswahl erwartet `_value` einen einzelnen Wert, bei der Mehrfachauswahl (`_multiple`) ein Array; passt die Form nicht dazu, wird der Wert nicht übernommen und ein Fehler in der Browser-Konsole ausgegeben. Werte, die in `_options` nicht vorkommen, werden verworfen. Ist bei der Einfachauswahl kein gültiger Wert gesetzt, wird – wie beim nativen `<select>` – automatisch die erste nicht deaktivierte Option ausgewählt.

**Wie gestalte ich die Optionen?**  
Stellen Sie die Optionen über `_options` als Array mit `label` und `value` bereit und verwenden Sie aussagekräftige und eindeutige Beschriftungen (`label`). Strukturieren Sie umfangreiche Auswahllisten mithilfe von [Optionsgruppen](#optionsgruppen). Vermeiden Sie deaktivierte Optionen, sofern dies fachlich möglich ist: Screenreader sagen sie mit an, sodass die Anzahl der angesagten Optionen von der Anzahl der tatsächlich auswählbaren Optionen abweichen kann.

**Soll ich eine Option vorauswählen oder eine Leer-Option anbieten?**  
Das hängt davon ab, ob es einen sinnvollen Standardwert gibt:

- Gibt es **einen sinnvollen, unstrittigen Standardwert**, wählen Sie ihn über `_value` vor und verzichten Sie auf eine Leer-Option. Das spart Zeit und Klicks und vermeidet Mehrdeutigkeit.
- Gibt es **keinen sinnvollen Standardwert** oder hat die **Auswahl rechtliche bzw. finanzielle Konsequenzen**, stellen Sie eine explizite, **klar beschriftete Leer-Option** (z. B. „Bitte auswählen“) bereit. So treffen Nutzende eine bewusste Entscheidung, werden nicht beeinflusst und können ihre Eingabe zurücksetzen.

Treffen Sie keine automatische Vorauswahl personenbezogener Optionen (z. B. Anreden), sofern diese nicht fachlich begründet ist. Verwenden Sie stattdessen eine neutrale Option, damit Nutzende ihre Auswahl bewusst treffen, oder eine **Radio Group**.

**Wie setze ich eine Leer-Option um und wie verhält sie sich mit `_required`?**  
Legen Sie die Leer-Option als erste Option in `_options` an, z. B. `{ label: 'Bitte auswählen', value: '' }`. Ohne gültigen `_value` wählt die Komponente bei der Einfachauswahl die erste nicht deaktivierte Option aus, also die Leer-Option; `getValue()` und die Events liefern dann deren `value`. Deaktivieren Sie die Leer-Option nicht – sonst wird sie übersprungen und die erste fachliche Option ist vorausgewählt. Auch die Leer-Option braucht ein nicht leeres `label`; eine Option mit leerem `label` macht die gesamte Optionsliste ungültig.

Setzen Sie `_required`, wenn eine Auswahl zwingend erforderlich ist. `_required` kennzeichnet das Feld als Pflichtfeld, prüft die Auswahl aber nicht: Ist die Leer-Option ausgewählt, zeigt die Komponente keine Fehlermeldung an. Prüfen Sie daher in der Anwendung, ob noch der Wert der Leer-Option ausgewählt ist, und zeigen Sie in diesem Fall über `_msg` eine Fehlermeldung an (siehe [Hinweistexte und Fehlermeldungen](#hinweistexte-und-fehlermeldungen)).

**Gibt es einen Platzhalter für die Select-Komponente?**  
Nein. Die Komponente unterstützt kein `_placeholder`. Nutzen Sie bei Bedarf eine klar beschriftete Leer-Option als erste Option (siehe oben).

**Unterstützt die Komponente Optionsgruppen?**  
Ja, siehe [Optionsgruppen](#optionsgruppen).

**Warum wirkt sich `_rows` bei meiner Auswahlliste nicht aus?**  
`_rows` wird nur in Verbindung mit `_multiple` ausgewertet. Bei der Einfachauswahl bleibt die Komponente ein aufklappbares Auswahlfeld.

**Warum verwendet die Komponente das native HTML-Element `<select>`?**  
Das native HTML-Element `<select>` stellt die erforderliche Semantik sowie die Unterstützung für Tastaturbedienung, Fokusverwaltung und Screenreader bereits bereit. Die KoliBri-Komponente ergänzt daher keine eigenen ARIA-Rollen und nutzt bewusst das standardisierte Verhalten des Browsers. Zusätzliche ARIA-Rollen (z. B. `role="combobox"` oder `role="listbox"`) sind nicht erforderlich und sollten nicht ergänzt werden.

### Mehrfachauswahl

Mit `_multiple` erlauben Sie die Auswahl mehrerer Optionen. Die Komponente wird dann nicht mehr als aufklappbares Auswahlfeld, sondern als Liste mit mehreren sichtbaren Zeilen dargestellt. `_value` erwartet in diesem Fall ein Array der ausgewählten Werte.

Mit `_rows` legen Sie fest, wie viele Optionen gleichzeitig sichtbar sind. `_rows` wird ausschließlich in Verbindung mit `_multiple` als natives `size`-Attribut gesetzt.

<SelectPreview
	context="feature"
	visibleProperties={['_multiple', '_rows']}
	initialProps={{
		_label: 'Bundesländer',
		_multiple: true,
		_rows: 5,
	}}
/>

### Optionsgruppen

Umfangreiche Auswahllisten strukturieren Sie mit Optionsgruppen. Eine Optionsgruppe wird in `_options` als Objekt mit `label` und einem eigenen Array `options` angegeben und als natives `optgroup`-Element ausgegeben. Die Beschriftung der Gruppe wird von Screenreadern beim Navigieren durch die Optionen mit angesagt; sie ist selbst nicht auswählbar.

Mit `disabled: true` an einer Optionsgruppe deaktivieren Sie alle Optionen dieser Gruppe.

<SelectPreview
	context="feature"
	visibleProperties={['_label']}
	initialProps={{
		_label: 'Bundesland',
		_options: [
			{ label: 'Bitte auswählen', value: '' },
			{
				label: 'Norddeutschland',
				options: [
					{ label: 'Bremen', value: 'HB' },
					{ label: 'Hamburg', value: 'HH' },
					{ label: 'Schleswig-Holstein', value: 'SH' },
				],
			},
			{
				label: 'Süddeutschland',
				options: [
					{ label: 'Baden-Württemberg', value: 'BW' },
					{ label: 'Bayern', value: 'BY' },
				],
			},
		],
	}}
/>

### Deaktivierte Optionen

Einzelne Optionen deaktivieren Sie über die Eigenschaft `disabled` der jeweiligen Option. Deaktivierte Optionen bleiben sichtbar und werden von Screenreadern angesagt, können aber nicht ausgewählt werden. Setzen Sie deaktivierte Optionen sparsam ein (siehe [FAQ](#faq)).

<SelectPreview
	context="feature"
	visibleProperties={['_options']}
	initialProps={{
		_label: 'Zustellart',
		_options: [
			{ label: 'Standardversand', value: 'standard' },
			{ label: 'Expressversand', value: 'express' },
			{ label: 'Abholung (derzeit nicht verfügbar)', value: 'pickup', disabled: true },
		],
	}}
/>

# Select


<BetaDocsBanner />

**Synonyme:** Dropdown, Dropdown-Liste, Auswahlliste, Auswahlfeld

**Beschreibung:** Mit **Select** wählen Nutzende eine oder mehrere Optionen aus einer vordefinierten Liste aus.

Die Komponente basiert auf dem nativen HTML-Element `<select>` und profitiert dadurch von dessen Semantik sowie der standardisierten Unterstützung durch Browser und assistive Technologien.

Sie eignet sich für strukturierte Eingaben, bei denen ausschließlich bekannte Werte zulässig sind und keine freie Texteingabe erfolgen soll. Je nach Konfiguration unterstützt die Komponente die **Einfachauswahl** als aufklappbares Auswahlfeld oder die **Mehrfachauswahl** als Liste mit mehreren sichtbaren Zeilen. Die auswählbaren Optionen werden über `_options` bereitgestellt und können mithilfe von **Optionsgruppen** logisch strukturiert werden.

## Barrierefreiheit

* <LabelNote />
* <ErrorMessageNote />
* Die Komponente ergänzt bewusst keine eigenen ARIA-Rollen wie `role="combobox"` oder `role="listbox"`. Rolle, Tastaturbedienung, Fokus-Handling und Ansageverhalten stammen vollständig vom nativen `<select>`-Element.
* Deaktivierte Optionen bleiben für assistive Technologien wahrnehmbar und werden von Screenreadern mitgezählt und angesagt. Dadurch kann die Anzahl der angesagten Optionen von der Anzahl der tatsächlich auswählbaren Optionen abweichen. Vermeiden Sie deaktivierte Optionen daher, sofern dies fachlich möglich ist.
* Bei der Mehrfachauswahl (`_multiple`) haben die Optionen eine Mindesthöhe, die den Anforderungen an barrierefreie Bedienelemente entspricht, damit sie auch mit Maus und Touch sicher getroffen werden können.
* Ausgewählte Optionen werden zusätzlich mit einem vorangestellten Häkchen gekennzeichnet, damit die Auswahl nicht allein über Farbe erkennbar ist. Die Darstellung hängt davon ab, ob der Browser die Optionsliste mit den Stilen der Komponente rendert.

### Konkrete Designentscheidungen

| Entscheidung | Begründung |
| ------------ | ---------- |
| Verwendung des nativen HTML-Elements `<select>` ohne zusätzliche ARIA-Rolle | Das native Element stellt die erforderliche Semantik sowie die Unterstützung für Tastaturbedienung, Fokusverwaltung und Screenreader bereits bereit. Zusätzliche ARIA-Rollen würden diese Semantik überlagern und sind daher nicht vorgesehen. |
| Deaktivierte Optionen ohne `aria-hidden` | Deaktivierte Optionen werden nicht vor assistiven Technologien verborgen, da Browser `aria-hidden` an Optionen ignorieren bzw. dadurch fehlerhaftes Verhalten entstand. Die Optionen bleiben deshalb im Accessibility-Tree. |
| `_rows` nur bei Mehrfachauswahl | `_rows` wird ausschließlich in Verbindung mit `_multiple` als natives `size`-Attribut gesetzt. Die Einfachauswahl bleibt dadurch immer ein aufklappbares Auswahlfeld mit einheitlicher Höhe. |
| Mindestgröße der Optionen bei Mehrfachauswahl | In der dauerhaft sichtbaren Liste der Mehrfachauswahl erhalten die Optionen eine Mindesthöhe, damit sie als Zielfläche für Maus und Touch ausreichend groß sind. |
| Häkchen vor ausgewählten Optionen | Die Auswahl wird zusätzlich über ein Zeichen und nicht ausschließlich über eine farbliche Hervorhebung vermittelt. |

## Verwendung

Die Select-Komponente eignet sich insbesondere für:

- die Auswahl einer oder mehrerer Optionen aus einer vordefinierten Menge an Werten,
- strukturierte Formulareingaben und standardisierte Datenerfassung,
- Einfach- und Mehrfachauswahlen.

Die Select-Komponente sollte **nicht** verwendet werden, wenn:

- freie Eingaben möglich sein sollen oder bei einer Einfachauswahl eine Such- oder Filterfunktion benötigt wird. Verwenden Sie stattdessen eine **Combobox**.
- genau eine Option aus einer kleinen Auswahl (ca. 1–5 Optionen) ausgewählt werden soll und alle Optionen gleichzeitig sichtbar sein sollen. Verwenden Sie stattdessen eine **Radio Group**.

**Hinweis:** Bei der Einfachauswahl erwartet `_value` einen einzelnen Wert, bei der Mehrfachauswahl (`_multiple`) ein Array. Werte, die in `_options` nicht vorkommen, werden verworfen. Ist bei der Einfachauswahl kein gültiger Wert gesetzt, wird – wie beim nativen `<select>` – automatisch die erste Option ausgewählt.

### Tastatursteuerung

<NativeKeyboardIntro />

| Taste                       | Funktion                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `Tab`                       | Fokus auf die Auswahlliste bzw. das nächste fokussierbare Element setzen.                                  |
| `Shift+Tab`                 | Fokus auf das vorherige fokussierbare Element setzen.                                                      |
| `Pfeil-Tasten (oben/unten)` | Zwischen den Optionen wechseln. Je nach Browser wird die Auswahl auch bei geschlossener Auswahlliste direkt geändert. |
| `Pos1` / `Ende`             | Zur ersten bzw. letzten Option springen.                                                                   |
| Buchstabentasten            | Zur nächsten Option springen, deren Beschriftung mit dem eingegebenen Zeichen beginnt.                     |
| `Leertaste` / `Enter`       | Auswahlliste öffnen bzw. die hervorgehobene Option übernehmen und die Auswahlliste schließen.              |
| `Alt+Pfeil-Taste unten`     | Auswahlliste öffnen (u. a. unter Windows).                                                                 |
| `Esc`                       | Geöffnete Auswahlliste schließen.                                                                          |

#### Bei Mehrfachauswahl (`_multiple`)

| Taste                        | Funktion                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `Pfeil-Tasten (oben/unten)`  | Fokus auf die nächste bzw. vorherige Option setzen und nur diese Option auswählen. |
| `Shift+Pfeil-Tasten`         | Auswahl um die hintereinanderliegenden Optionen erweitern.                        |
| `Strg+Pfeil-Tasten`          | Fokus verschieben, ohne die bestehende Auswahl zu verändern.                      |
| `Strg+Leertaste`             | Fokussierte Option zur Auswahl hinzufügen bzw. aus ihr entfernen.                 |

**Hinweis:** Unter macOS wird statt `Strg` in der Regel die `Cmd`-Taste verwendet.

### Best Practices / Empfehlungen

**Auswahl der geeigneten Komponente**

- Verwenden Sie die Select-Komponente ausschließlich für vordefinierte Auswahlmöglichkeiten.
- Nutzen Sie `_multiple` nur, wenn eine Mehrfachauswahl fachlich erforderlich ist. Die Mehrfachauswahl erfordert Tastenkombinationen, die vielen Nutzenden nicht bekannt sind. Prüfen Sie, ob stattdessen eine **Checkbox Group** besser geeignet ist.
- Prüfen Sie bei umfangreichen Auswahllisten, ob eine **Combobox** die geeignetere Komponente ist.

**Gestaltung der Optionen**

- Stellen Sie die Optionen über `_options` als Array mit `label` und `value` bereit.
- Strukturieren Sie umfangreiche Auswahllisten mithilfe von **Optionsgruppen**.
- Verwenden Sie aussagekräftige und eindeutige Beschriftungen (`label`).
- Setzen Sie `_required`, wenn eine Auswahl zwingend erforderlich ist.

**Vorauswahl und Leer-Option**

- Treffen Sie keine automatische Vorauswahl personenbezogener Optionen (z. B. Anreden), sofern diese nicht fachlich begründet ist. Verwenden Sie stattdessen eine neutrale Option, damit Nutzende ihre Auswahl bewusst treffen, oder eine **Radio Group**.
- Sofern aus der Auswahlliste ein sinnvoller Standardwert hervorgeht, sollte dieser über `_value` vorausgewählt werden. In diesem Fall sollte keine Leer-Option verwendet werden.
- Falls kein sinnvoller Standardwert existiert oder die Auswahl rechtliche bzw. finanzielle Konsequenzen hat, stellen Sie eine explizite, klar beschriftete Leer-Option (z. B. „Bitte auswählen“) als erste Option in `_options` bereit. Die Komponente bietet hierfür keinen eigenen Platzhalter an.

### Anwendungsfälle

- Auswahl eines Bundeslandes
- Sprachauswahl
- Auswahl einer Organisationseinheit oder eines Fachbereichs
- Kategorieauswahl in Formularen
- Statusauswahl aus mehreren festgelegten Bearbeitungsständen

### FAQ

**Wann eignet sich eine Combobox besser?**  
Wenn eine große Anzahl an Optionen zur Verfügung steht oder Nutzende gezielt nach Einträgen suchen sollen.

**Wann eignet sich eine Radio Group besser?**  
Wenn genau eine Option aus einer kleinen Anzahl (ca. 1–5 Optionen) ausgewählt werden soll und alle Optionen gleichzeitig sichtbar sein können.

**Unterstützt die Komponente Optionsgruppen?**  
Ja. `_options` unterstützt neben einzelnen Optionen auch Optionsgruppen (`{ label, options }`), die als native `optgroup`-Elemente ausgegeben werden.

**Warum wirkt sich `_rows` bei meiner Auswahlliste nicht aus?**  
`_rows` wird nur in Verbindung mit `_multiple` ausgewertet. Bei der Einfachauswahl bleibt die Komponente ein aufklappbares Auswahlfeld.

**Gibt es einen Platzhalter für die Select-Komponente?**  
Nein. Die Komponente unterstützt kein `_placeholder`. Nutzen Sie bei Bedarf eine klar beschriftete Leer-Option als erste Option.

### Mehrfachauswahl

Mit `_multiple` erlauben Sie die Auswahl mehrerer Optionen. Die Komponente wird dann nicht mehr als aufklappbares Auswahlfeld, sondern als Liste mit mehreren sichtbaren Zeilen dargestellt. `_value` erwartet in diesem Fall ein Array der ausgewählten Werte.

Mit `_rows` legen Sie fest, wie viele Optionen gleichzeitig sichtbar sind. `_rows` wird ausschließlich in Verbindung mit `_multiple` als natives `size`-Attribut gesetzt.

<SelectPreview
	context="feature"
	visibleProperties={['_multiple', '_rows']}
	initialProps={{
		_label: 'Bundesländer',
		_multiple: true,
		_rows: 5,
	}}
/>

### Optionsgruppen

Umfangreiche Auswahllisten strukturieren Sie mit Optionsgruppen. Eine Optionsgruppe wird in `_options` als Objekt mit `label` und einem eigenen Array `options` angegeben und als natives `optgroup`-Element ausgegeben. Die Beschriftung der Gruppe wird von Screenreadern beim Navigieren durch die Optionen mit angesagt; sie ist selbst nicht auswählbar.

<SelectPreview
	context="feature"
	visibleProperties={['_label']}
	initialProps={{
		_label: 'Bundesland',
		_options: [
			{
				label: 'Norddeutschland',
				options: [
					{ label: 'Bremen', value: 'HB' },
					{ label: 'Hamburg', value: 'HH' },
					{ label: 'Schleswig-Holstein', value: 'SH' },
				],
			},
			{
				label: 'Süddeutschland',
				options: [
					{ label: 'Baden-Württemberg', value: 'BW' },
					{ label: 'Bayern', value: 'BY' },
				],
			},
		],
	}}
/>

### Deaktivierte Optionen

Einzelne Optionen deaktivieren Sie über die Eigenschaft `disabled` der jeweiligen Option. Deaktivierte Optionen bleiben sichtbar und werden von Screenreadern angesagt, können aber nicht ausgewählt werden. Setzen Sie deaktivierte Optionen sparsam ein (siehe [Barrierefreiheit](#barrierefreiheit)).

<SelectPreview
	context="feature"
	visibleProperties={['_options']}
	initialProps={{
		_label: 'Zustellart',
		_options: [
			{ label: 'Standardversand', value: 'standard' },
			{ label: 'Expressversand', value: 'express' },
			{ label: 'Abholung (derzeit nicht verfügbar)', value: 'pickup', disabled: true },
		],
	}}
/>
